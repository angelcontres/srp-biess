# 16. Anexos — SDD

**Proyecto:** Sistema de Registro y Postulación al Directorio del BIESS (SRP-BIESS)  
**Módulo:** EF-11 (registro y autenticación) y EF-12 (formulario de postulación)  
**Versión:** 1.0  
**Fecha:** 31/10/2026  
**Estándar de referencia:** IEEE 1016-2009

## 16.1 Propósito y contenido

Este capítulo reúne los artefactos de referencia que complementan el diseño: el DDL ejecutable, el seed mínimo, las variables de entorno, ejemplos de API, el glosario, las decisiones pendientes y las listas de verificación para la entrega y la sustentación.

### Convenciones

- El DDL está pensado para **PostgreSQL 16** y se ejecuta con un usuario propietario del esquema.
- Las fechas de la base se almacenan en `timestamptz` (UTC); la aplicación presenta `America/Guayaquil`.
- Los datos de ejemplo son ficticios. No se debe usar información real de personas.
- Los identificadores de negocio son `uuid`; los catálogos usan enteros pequeños y la auditoría usa `bigserial`.
- Los límites de archivos son 4 MB para respaldo organizacional, 2 MB para los demás PDF de postulación y 50 MB acumulados por postulante.
- Los estados de postulación son `BORRADOR`, `LISTA_PARA_ENVIO`, `ENVIADA`, `EN_REVISION`, `NO_ELEGIBLE` y `CERRADA`.

## 16.2 Anexo A — DDL completo de PostgreSQL

### 16.2.1 Script de creación

> **Orden de ejecución:** crear la base `srp_biess`, conectarse con el usuario propietario y ejecutar el script completo. En producción, aplicar como migración versionada y con un usuario dedicado. No ejecutar `DROP SCHEMA` sobre una base con datos.

```sql

-- SRP-BIESS · Esquema PostgreSQL 16
-- Módulo EF-11 (registro/autenticación) y EF-12 (postulación)
-- Ejecutar con un usuario propietario del esquema.

-- ---------------------------------------------------------------------
-- 2. Catálogos geográficos y del concurso
-- ---------------------------------------------------------------------
CREATE TABLE pais (
  id            smallint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  codigo_iso2   char(2) NOT NULL UNIQUE,
  codigo_iso3   char(3) NOT NULL UNIQUE,
  nombre        varchar(120) NOT NULL,
  activo        boolean NOT NULL DEFAULT true,
  created_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_pais_iso2 CHECK (codigo_iso2 ~ '^[A-Z]{2}$'),
  CONSTRAINT ck_pais_iso3 CHECK (codigo_iso3 ~ '^[A-Z]{3}$')
);

CREATE TABLE provincia (
  id            smallint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  pais_id       smallint NOT NULL REFERENCES pais(id) ON DELETE RESTRICT,
  codigo        char(2) NOT NULL,
  nombre        varchar(120) NOT NULL,
  activo        boolean NOT NULL DEFAULT true,
  created_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_provincia_pais_codigo UNIQUE (pais_id, codigo),
  CONSTRAINT ck_provincia_codigo CHECK (codigo ~ '^[0-9]{2}$')
);

CREATE TABLE canton (
  id            integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  provincia_id  smallint NOT NULL REFERENCES provincia(id) ON DELETE RESTRICT,
  codigo        char(4) NOT NULL,
  nombre        varchar(120) NOT NULL,
  activo        boolean NOT NULL DEFAULT true,
  created_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_canton_provincia_codigo UNIQUE (provincia_id, codigo),
  CONSTRAINT ck_canton_codigo CHECK (codigo ~ '^[0-9]{4}$')
);

CREATE TABLE cargo (
  id            smallint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  codigo        varchar(3) NOT NULL UNIQUE,
  nombre        varchar(200) NOT NULL,
  sector        sector_cargo NOT NULL,
  activo        boolean NOT NULL DEFAULT true,
  created_at    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_cargo_codigo CHECK (codigo IN ('AFI', 'JUB', 'EMP'))
);

CREATE TABLE convocatoria (
  id                            integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  codigo                        varchar(30) NOT NULL UNIQUE,
  nombre                        varchar(200) NOT NULL,
  fecha_inicio_postulacion      date NOT NULL,
  fecha_fin_postulacion         date NOT NULL,
  fase_postulacion_habilitada   boolean NOT NULL DEFAULT false,
  version_formulario            varchar(20) NOT NULL,
  created_at                    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_convocatoria_fechas CHECK (fecha_fin_postulacion >= fecha_inicio_postulacion)
);

-- 3. Postulante y datos personales

CREATE TABLE postulante (
  id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  cedula                char(10) NOT NULL,
  nombres               varchar(150) NOT NULL,

  nacionalidad_pais_id  smallint NOT NULL REFERENCES pais(id) ON DELETE RESTRICT,

  correo                varchar(254) NOT NULL,
  password_hash         varchar(255) NOT NULL,

  ultimo_acceso         timestamptz,
  version               integer NOT NULL DEFAULT 1,

  CONSTRAINT ck_postulante_correo CHECK (correo ~ '^[^@[:space:]]+@[^@[:space:]]+\.[^@[:space:]]+$'),
  CONSTRAINT ck_postulante_password_hash CHECK (length(password_hash) >= 20),
  CONSTRAINT ck_postulante_version CHECK (version > 0)
);

CREATE TABLE pareja_postulante (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulante_id     uuid NOT NULL UNIQUE REFERENCES postulante(id) ON DELETE CASCADE,

  cedula            char(10) NOT NULL,
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_pareja_cedula CHECK (cedula ~ '^[0-9]{10}$')
);

CREATE TABLE domicilio_postulante (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulante_id       uuid NOT NULL UNIQUE REFERENCES postulante(id) ON DELETE CASCADE,
  pais_id             smallint NOT NULL REFERENCES pais(id) ON DELETE RESTRICT,
  provincia_id        smallint REFERENCES provincia(id) ON DELETE RESTRICT,
  canton_id           integer REFERENCES canton(id) ON DELETE RESTRICT,
  provincia_manual    varchar(120),
  ciudad_manual       varchar(120),
  telefono_celular    varchar(20) NOT NULL,
  correo_alterno      varchar(254),
  calle_principal     varchar(200) NOT NULL,
  numero              varchar(20),
  calle_secundaria    varchar(200),
  sector              varchar(120),
  referencia          varchar(300),
  telefono_domicilio  varchar(20),
  created_at          timestamptz NOT NULL DEFAULT now(),
  updated_at          timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_domicilio_celular CHECK (telefono_celular ~ '^\+?[0-9][0-9 ()-]{6,19}$'),
  CONSTRAINT ck_domicilio_telefono CHECK (telefono_domicilio IS NULL OR telefono_domicilio ~ '^\+?[0-9][0-9 ()-]{6,19}$'),
  CONSTRAINT ck_domicilio_correo CHECK (correo_alterno IS NULL OR correo_alterno ~ '^[^@[:space:]]+@[^@[:space:]]+\.[^@[:space:]]+$'),
  CONSTRAINT ck_domicilio_ubicacion CHECK (
    (provincia_id IS NOT NULL OR provincia_manual IS NOT NULL)
    AND (canton_id IS NOT NULL OR ciudad_manual IS NOT NULL)

CREATE TABLE familiar_institucion (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulante_id     uuid NOT NULL REFERENCES postulante(id) ON DELETE CASCADE,
  nombres_apellidos varchar(300) NOT NULL,
  parentesco        parentesco_familiar NOT NULL,

  cargo             varchar(150) NOT NULL,
  created_at        timestamptz NOT NULL DEFAULT now(),
  updated_at        timestamptz NOT NULL DEFAULT now()

-- ---------------------------------------------------------------------
-- 4. Postulación
-- ---------------------------------------------------------------------
CREATE TABLE postulacion (
  id                          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  codigo_unico                varchar(30),
  postulante_id               uuid NOT NULL REFERENCES postulante(id) ON DELETE RESTRICT,
  convocatoria_id             integer NOT NULL REFERENCES convocatoria(id) ON DELETE RESTRICT,
  cargo_id                    smallint REFERENCES cargo(id) ON DELETE RESTRICT,
  estado                      estado_postulacion NOT NULL DEFAULT 'BORRADOR',
  fecha_creacion              timestamptz NOT NULL DEFAULT now(),
  fecha_guardado              timestamptz,
  fecha_envio                 timestamptz,
  elegibilidad_estado         varchar(20) NOT NULL DEFAULT 'PENDIENTE',
  elegibilidad_motivo         text,
  requiere_revision           boolean NOT NULL DEFAULT false,
  tiene_familiares_institucion boolean,
  tiene_publicaciones         boolean,
  ultima_seccion              varchar(40),
  version                     integer NOT NULL DEFAULT 1,
  CONSTRAINT uq_postulacion_id_postulante UNIQUE (id, postulante_id),
  CONSTRAINT ck_postulacion_codigo_formato CHECK (
    codigo_unico IS NULL OR codigo_unico ~ '^BIESS-[0-9]{4}-(AFI|JUB|EMP)-[0-9]{6}$'
  ),
  CONSTRAINT ck_postulacion_codigo_estado CHECK (
    codigo_unico IS NULL OR estado IN ('ENVIADA', 'EN_REVISION', 'NO_ELEGIBLE', 'CERRADA')
  ),
  CONSTRAINT ck_postulacion_sin_codigo_borrador CHECK (
    estado NOT IN ('BORRADOR', 'LISTA_PARA_ENVIO') OR codigo_unico IS NULL
  ),
  CONSTRAINT ck_postulacion_codigo_enviada CHECK (
    estado NOT IN ('ENVIADA', 'EN_REVISION') OR codigo_unico IS NOT NULL
  ),
  CONSTRAINT ck_postulacion_fecha_envio CHECK (
    fecha_envio IS NULL OR fecha_envio >= fecha_creacion
  ),
  CONSTRAINT ck_postulacion_envio_requerido CHECK (
    estado NOT IN ('ENVIADA', 'EN_REVISION') OR fecha_envio IS NOT NULL
  ),
  CONSTRAINT ck_postulacion_elegibilidad CHECK (
    elegibilidad_estado IN ('PENDIENTE', 'ELEGIBLE', 'NO_ELEGIBLE', 'INDETERMINADO')
  ),
  CONSTRAINT ck_postulacion_seccion CHECK (
    ultima_seccion IS NULL OR ultima_seccion IN (
      'personal', 'domicilio', 'familiares', 'cargo', 'formacion',
      'experiencia', 'publicaciones', 'capacitacion', 'inhabilidades', 'consentimiento'
    )
  ),
  CONSTRAINT ck_postulacion_version CHECK (version > 0)
);

CREATE SEQUENCE seq_codigo_postulacion
  AS bigint
  START WITH 1
  INCREMENT BY 1
  NO CYCLE;

COMMENT ON SEQUENCE seq_codigo_postulacion IS
  'Secuencia global para el consecutivo del código BIESS-{AÑO}-{SECTOR}-{SECUENCIA}.';
COMMENT ON COLUMN postulacion.codigo_unico IS
  'Se asigna al enviar; formato BIESS-AAAA-SECTOR-000000.';
COMMENT ON COLUMN postulacion.tiene_familiares_institucion IS
  'NULL = no respondido; true/false = declaración explícita.';
COMMENT ON COLUMN postulacion.tiene_publicaciones IS
  'NULL = no respondido; true/false = declaración explícita.';

-- ---------------------------------------------------------------------
-- 5. Documentos
-- ---------------------------------------------------------------------
CREATE TABLE documento (
  id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulante_id     uuid NOT NULL REFERENCES postulante(id) ON DELETE CASCADE,
  postulacion_id    uuid,
  tipo              tipo_documento NOT NULL,
  nombre_original   varchar(255) NOT NULL,
  nombre_almacenado varchar(255) NOT NULL UNIQUE,
  mime_type         varchar(100) NOT NULL DEFAULT 'application/pdf',
  tamano_bytes      bigint NOT NULL,
  hash_sha256       char(64) NOT NULL,
  ruta              text NOT NULL,
  estado            estado_documento NOT NULL DEFAULT 'PENDIENTE',
  created_at        timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT fk_documento_postulacion_owner
    FOREIGN KEY (postulacion_id, postulante_id)
    REFERENCES postulacion (id, postulante_id)
    ON DELETE CASCADE,
  CONSTRAINT ck_documento_mime CHECK (mime_type = 'application/pdf'),
  CONSTRAINT ck_documento_tamano CHECK (tamano_bytes > 0),
  CONSTRAINT ck_documento_hash CHECK (hash_sha256 ~ '^[a-f0-9]{64}$'),
  CONSTRAINT ck_documento_limite_tipo CHECK (
    (tipo = 'RESPALDO_ORGANIZACIONAL' AND tamano_bytes <= 4194304)
    OR (tipo IN ('TITULO', 'EXPERIENCIA', 'PUBLICACION', 'CAPACITACION') AND tamano_bytes <= 2097152)
    OR (tipo = 'FORMULARIO_POSTULACION')
  ),
  CONSTRAINT ck_documento_formulario CHECK (
    tipo <> 'FORMULARIO_POSTULACION' OR postulacion_id IS NOT NULL
  )
);

COMMENT ON TABLE documento IS
  'Metadatos de PDF; el archivo se guarda fuera de la base y del directorio público.';

CREATE TABLE respaldo_organizacional (
  id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulacion_id      uuid NOT NULL UNIQUE REFERENCES postulacion(id) ON DELETE CASCADE,
  tiene_respaldo      boolean NOT NULL,
  nombre_organizacion varchar(200),
  documento_id        uuid REFERENCES documento(id) ON DELETE SET NULL,

  CONSTRAINT ck_respaldo_declaracion CHECK (

  )

CREATE TABLE formacion_academica (
  id                       uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulacion_id           uuid NOT NULL REFERENCES postulacion(id) ON DELETE CASCADE,

CREATE TABLE experiencia_profesional (
  id                       uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  postulacion_id           uuid NOT NULL REFERENCES postulacion(id) ON DELETE CASCADE,
  tipo_experiencia         tipo_experiencia NOT NULL,
  cargo_puesto             varchar(200) NOT NULL,
  institucion_empresa      varchar(200) NOT NULL,
  fecha_inicio             date NOT NULL,
  fecha_fin                date,
  actualmente              boolean NOT NULL DEFAULT false,
  actividades_relacionadas text,
  descripcion_funciones    varchar(1000) NOT NULL,
  tiempo_anios             smallint NOT NULL DEFAULT 0,
  tiempo_meses             smallint NOT NULL DEFAULT 0,
  tiempo_dias              smallint NOT NULL DEFAULT 0,
  documento_id             uuid REFERENCES documento(id) ON DELETE SET NULL,
  created_at               timestamptz NOT NULL DEFAULT now(),
  updated_at               timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT ck_experiencia_fechas CHECK (fecha_fin IS NULL OR fecha_fin >= fecha_inicio),
  CONSTRAINT ck_experiencia_actualidad CHECK (
    (actualmente = true AND fecha_fin IS NULL)
    OR (actualmente = false AND fecha_fin IS NOT NULL)

  CONSTRAINT ck_experiencia_tiempo CHECK (
    tiempo_anios >= 0 AND tiempo_meses BETWEEN 0 AND 11 AND tiempo_dias BETWEEN 0 AND 30

  fecha_inicio    date NOT NULL,
  fecha_fin       date NOT NULL,
  numero_horas    integer NOT NULL,
  documento_id    uuid REFERENCES documento(id) ON DELETE SET NULL,

  created_at            timestamptz NOT NULL DEFAULT now(),

    (institucion_remocion IS NULL AND cargo_remocion IS NULL AND fecha_fin_remocion IS NULL AND motivo_remocion IS NULL)

CREATE OR REPLACE FUNCTION fn_proteger_postulacion_enviada()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  IF OLD.estado IN ('ENVIADA', 'EN_REVISION', 'CERRADA') THEN
    IF NEW.codigo_unico IS DISTINCT FROM OLD.codigo_unico
       OR NEW.postulante_id IS DISTINCT FROM OLD.postulante_id
       OR NEW.convocatoria_id IS DISTINCT FROM OLD.convocatoria_id
       OR NEW.cargo_id IS DISTINCT FROM OLD.cargo_id
       OR NEW.fecha_envio IS DISTINCT FROM OLD.fecha_envio THEN
      RAISE EXCEPTION 'La postulación enviada es inmutable'
        USING ERRCODE = '55000';
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_postulacion_inmutable
  BEFORE UPDATE ON postulacion
  FOR EACH ROW EXECUTE FUNCTION fn_proteger_postulacion_enviada();

CREATE OR REPLACE FUNCTION fn_bloquear_borrado_postulacion()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  IF OLD.estado <> 'BORRADOR' THEN
    RAISE EXCEPTION 'Solo se pueden eliminar postulaciones en estado BORRADOR'
      USING ERRCODE = '55000';
  END IF;
  RETURN OLD;
END;
$$;

CREATE TRIGGER trg_postulacion_no_borrar
  BEFORE DELETE ON postulacion
  FOR EACH ROW EXECUTE FUNCTION fn_bloquear_borrado_postulacion();
```

### 16.2.3 Decisiones materializadas en el DDL

1. **Unicidad del borrador vigente:** el índice parcial `uq_postulacion_vigente` impide más de una postulación no cerrada por postulante y convocatoria. `CERRADA` queda fuera porque representa el histórico.
2. **Código único:** la secuencia `seq_codigo_postulacion` entrega el consecutivo; el servicio compone `BIESS-{AÑO}-{SECTOR}-{SECUENCIA}`. El `CHECK` valida el formato y exige código cuando el estado es `ENVIADA` o `EN_REVISION`.
3. **Inmutabilidad:** el trigger `trg_postulacion_inmutable` bloquea cambios en código, dueño, convocatoria, cargo y fecha de envío cuando la postulación ya fue enviada. El trigger `trg_postulacion_no_borrar` solo permite eliminar borradores.
4. **Auditoría append-only:** `trg_auditoria_append_only` rechaza `UPDATE` y `DELETE`. El rol de aplicación debe recibir solo `INSERT` y `SELECT` sobre esta tabla.
5. **Documentos:** la FK compuesta `(postulacion_id, postulante_id)` evita asociar un PDF a una postulación de otro postulante. Los `CHECK` aplican los límites de 4 MB y 2 MB; el total de 50 MB se valida en el servicio porque requiere sumar filas.
6. **Declaraciones negativas:** `tiene_familiares_institucion` y `tiene_publicaciones` distinguen “no respondido” (`NULL`) de “respondí No” (`false`). La ausencia de filas no se usa como sustituto de la declaración.
7. **Inhabilidades:** `respuesta_bloqueante` guarda la respuesta binaria que activa el efecto. Para 1.9.1 es `false` porque “No” bloquea; en las preguntas de alerta es `NULL` y la respuesta “Sí” marca revisión.
8. **Consentimiento:** `textos_aceptados` conserva la evidencia de los cinco textos y `version_terminos` permite reconstruir qué versión aceptó el postulante.
9. **Outbox:** `notificacion` se inserta en la misma transacción del envío. El worker procesa `PENDIENTE`, incrementa `intentos` y actualiza `fecha_envio` o `error`.
10. **Concurrencia:** `postulacion.version` y `postulante.version` soportan el control optimista. La actualización debe incluir `WHERE id = $1 AND version = $2`.
